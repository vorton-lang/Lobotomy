# 前端

> Status: 设计决定；§7 写现在的实现
> 依据：[#6](https://github.com/vorton-lang/Lobotomy/issues/6) §5；对 20 个 agent GUI 产品的调研（issue、PR、源码，见 [research/frontend-survey.md](research/frontend-survey.md)）；本机 Codex / Claude 桌面应用的依赖扫描。

## 0. 原则

- **后端是权威，前端只是投影。** UI 卡顿、重载或重连后，前端从快照加序号重新同步。正确性不依赖 UI 及时消费每个事件（#6 §5）。重新同步只覆盖后端仍在运行的情况，不是后端崩溃恢复（见 §3 第 2 条）。
- **长对话、多路并行流式输出、单条巨量输出是常规负载。** 性能从第一天就设计和测量，不在功能完成后再补。
- **不依赖平台特有行为。** 先在 Windows 上开发，正式发版前修 Linux 问题。

## 1. 形态与进程

```text
Rust 后端（独立进程，常驻） ←── WebSocket ──→ Electron 渲染进程（React + TypeScript）
                                              Electron 主进程：窗口、托盘、系统通知
```

- 渲染进程直接用 WebSocket 连接后端；这个服务也为 role 提供 MCP。Electron 主进程不转发业务数据，保持空闲。浏览器同样可以连接，方便开发调试。
- 关闭窗口不退出，托盘常驻。关闭 GUI 不改变组织的运行意愿（#5）。
- **后端的启动与停止**（用户定）：
  1. Electron 启动时，如果后端没在运行，就启动它：`lobotomyd --host-dir <host 目录>`。一个后端管理所有项目（data-model.md §10）。后端与 Electron 分离，Electron 崩溃不带走后端。
  2. 后端监听后，在 host 目录写入 `backend.json`（端口与 pid），正常停止时删除。Electron 据此找到正在运行的后端。
  3. 关闭窗口时，窗口退到托盘，所有项目照常运行。
  4. 托盘菜单"退出 Lobotomy"按正常停止进行（harness-adapter.md §1.8）：中断所有项目正在运行的 turn，等它们退出，然后后端退出。退出 GUI 就是停止组织。
- **GUI 接口的访问控制**（用户定）：
  - 后端只监听 `127.0.0.1`。每个 GUI 连接都要带 token。token 在第一次启动时生成，存放在 host 目录（`%LOCALAPPDATA%\Lobotomy\gui-token`），Electron 从那里读取；它不进入 role 的环境。
  - 后端校验 `Host` 与 `Origin`，挡住网页的连接。允许的 Origin：没有 Origin、`file://`、本机地址（开发时的 Vite）。
  - 边界：这能挡住网页和误调用，挡不住存心读取 token 文件的 agent。同一 OS 用户下做不到真正的隔离（#6）。不把 token 只放在内存里，是因为那样 GUI 进程重启后连不回仍在运行的后端。
- **通知**：后端按 [manager-actions.md](manager-actions.md) §6 的规则判定，并持久保存通知意图；Electron 主进程用跨平台的 Notification API 投递。GUI 进程不在时意图保留，下次打开时在界面内显示，不补发系统通知。以上未实现，列入 roadmap 待排：现在还没有系统通知，只在窗口标题与托盘上显示"等你决定"的条数。
- 先例：Codex 桌面应用就是 Electron 前端加独立的 Rust app-server（JSON-RPC）。

## 2. 布局

窗口最上面是顶栏。顶栏下面，左侧是项目列表，右边显示列表中选中的一项：「全部」或一个项目。两种视图都由主区和右侧栏组成。界面的改进计划见 [ui-ux-plan.md](ui-ux-plan.md)。

- **项目列表**：最上面是「全部」。每个项目显示名称、"等你决定"的条数，以及是否有 turn 在运行。打不开的项目显示原因、「重试打开」和「归档」。已归档的项目收在列表末尾，默认收起。列表下方是「+ 新项目」。
- **「全部」**：主区是与 Angela 的对话。右侧栏上面是所有项目的"等你决定"，下面是只读的"共识"。Angela 打不开时，「全部」写明原因，并列出所有项目的"等你决定"。
- **项目**：主区是这个项目执行者的 Thread：用户的消息、它的回复与工具调用、汇报、运行时的消息（例如退回的理由）。右侧栏是这个项目的"等你决定"和 Workboard（[roles-and-tasks.md](roles-and-tasks.md) §3）。点开任务，在任务面板中看交付说明，验收或退回（§7.4）。直接通路是常设的二等入口，不是临时方案（[#23](https://github.com/vorton-lang/Lobotomy/issues/23)，用户定）。
  - 项目页没有输入框（#86，用户定）。项目的执行者是 worker，不在后端运行；不带任务发给它的消息没有人接。给 worker 的消息经过它的任务：等你决定卡片中的回复，以及任务面板中的退回。
  - 项目还没有 worker 时，主区写明在 host 目录的 `workers.toml` 中加一个写着这个项目名的条目，重启后生效（#94）。
  - `workers.toml` 读不出来时，所有 worker 都没有启动。「全部」和每个项目的右侧栏最上面写明这一点和出错的位置，改好后要重启（tech-plan.md §7 第 7 组）。
- **顶栏**：在项目中显示仓库名；在「全部」中显示"全部项目"。
- **role play 只在展示层**：名字，以及每个角色一个标识色和头像（§7.15）。
- ⚙ 设置是单独的页面，见 §7.8。
- **列宽可以拖拽调整**（用户定）：项目列表、右侧栏和任务面板的边缘可以拖动，也可以聚焦后用方向键调整，双击恢复默认宽度。宽度保存在本机的 localStorage 中，读写失败时用默认宽度。弹窗可以从右下角拖动改变大小。

**"等你决定"** 是唯一需要用户动手的一块。

- 「全部」汇总所有项目的条目，进入项目后只显示这个项目的条目。窗口标题与托盘上的条数是全局汇总的条数。这是用户定的规则（data-model.md §10.5）。
- 「全部」与项目中的"等你决定"都按类型分组（要你回答、出了问题、等你验收），每张卡片标出项目（用户定，[ui-ux-plan.md](ui-ux-plan.md) §7 第 2 条）。未实现，由界面改进专项的 P3 实现。现在「全部」中按项目分组：额度受阻不属于任何项目，归在"本机"一组，只算一条；Angela 的条目归在 Angela 一组。
- 「全部」中，项目的条目只有一行摘要和「前往」：卡片上的操作要用到这个项目的快照，所以在项目中处理。「前往」切到这个项目，条目关于某个任务时，同时打开它的任务面板。"本机"的额度受阻可以直接重试。
- Angela 用 `ask_user` 提的问题列在 Angela 一组，卡片上可以直接回复。你在提问之后发给她的消息送到她时，问题关闭（manager-actions.md §6）。

**与 Angela 有关的显示**：

- Angela 回复中的引用（manager-actions.md §2.1）：`[[quote:…]]` 显示为你的原话和时间；`[[att:…]]` 显示为一行附件，写明项目、来源和当前状态。点开附件，切到那个项目并打开任务面板。引用无效时，显示原因。
- 与 Angela 的对话中，你可以像即时通讯软件那样"回复"某一条，指定这条消息在回复什么。所有角色都按你选的对象执行（manager-actions.md §1.1）。转发后，你的消息下写明转给了谁、附了什么上下文。
- 执行者调用 `flag_mismatch` 时，与 Angela 的对话中出现一条 Lobotomy 消息，用户直接看到（manager-actions.md §2.3）。
- "共识"只读：Angela 记下且仍然有效的目标、阶段、决定、约束和待定，按全局和项目分组，各附依据的你的原话。被取代或已失效的不列出，推测不显示。用户直接修改共识未实现，列入 roadmap 待排（manager-actions.md §3.3）。
- 任务面板中，Angela 派的任务显示她引用的原话、她的解读、允许的动作和停止条件。暂停的任务写明是你还是 Angela 暂停的。

**设计了、还没有实现的部分**（未实现，列入 roadmap 待排）：

- 对话中的会议卡片与「拉会」，`ask_user` 问题的选项按钮。
- "等你决定"中待确认的对外操作和会议提议（manager-actions.md §4、§5）。
- **会议进行中**：主区换成会议记录，顶部显示参会者和"结束会议"，右侧栏不变。
- **Inspector**：点击角色名从右侧滑出。

  | 标签页 | 内容 |
  |---|---|
  | 状态 | harness / 模型、会话 ID 与时长、上下文用量、缓存命中、额度、当前任务与执行轮、语义检查点、新出现的工具提示 |
  | 输出 | 该 role 的全部产出，包括未呈现给用户的 |
  | 改动 | 按执行轮列出成果。成果的形态随 worker 层的替换重新设计（#86） |
  | 操作 | 继续会话 / 存检查点后开新会话 / 暂停 / 在官方应用中打开、交还（待排，见 [roadmap.md](roadmap.md)）。模型与推理强度已在设置中选择（§7.8） |

  Angela 的 Inspector 多一项"推测"。

## 3. 后端与前端的协议

1. **数据模型参照 Codex 的 Thread → Turn → Item。** 完成的 item 是权威状态，流式增量只用于实时显示。Turn 就是业务上的 turn（一次 CLI 进程运行），使用同一个 turn_id（[data-model.md](data-model.md) §3）。
2. **增量在 Rust 中合并，永不落库（#7）。**
   - 流式 partial 只保存在后端内存中。后端崩溃时，partial 丢失。实测中只有 Claude 的模型文本会流式到达；Codex 的文本和两家的工具输出都在完成后整块到达（harness-adapter.md §1.4）。工具运行期间，GUI 显示命令与已运行时间。运行时不为未完成的展示输出做 checkpoint。
   - 每个 item 在自身完成时写入 SQLite，不等整个 turn 结束。
   - 业务命令发生时立即写入 SQLite，与 CLI turn 是否结束无关。
   - 大内容放在文件中，数据库只保存元数据和引用。
   - 反例：t3code 一条 1 万字回复写出 3024 条 SQLite 事件且越用越卡；Cline 逐片重存快照，数据库涨到 1.66 GB。
3. **按 agent 分别节流。** 正在看的 agent 约每 16ms 推送一次，后台 agent 每 150–400ms 一次；推送状态消息前先发完积压的文本（Kilo）。未实现，列入 roadmap 待排；现状见 §7.14。
4. **每个 Thread 一个单调递增序号**（[data-model.md](data-model.md) §7.6）。
   - 重连时，前端先订阅，再拉取某个序号时刻的快照，然后应用该序号之后的增量。后端仍在运行时，快照包含已合并的当前 partial、已完成的 item 和对应序号（#7）。
   - 重放缓冲有上限，溢出时明确发出"重新拉取快照"信号，绝不悄悄丢弃。反例：Goose 的传输队列溢出后悄悄断开订阅，部分会话从此无法打开。
   - 加心跳与卡死检测，应对悄无声息断掉的 TCP 连接。
5. **通知只说什么变了，不携带内容。** 内容由前端按需拉取。超大输出由后端保存全文，只推送开头、结尾与总大小；用户展开时按行范围拉取。存储方式见 data-model.md §7.3。
6. **打开会话从末尾加载。** 只取最近 N 条，更早的内容在向上滚动时分页加载。Goose 只重放最近 200 条后，加载从 3.85 秒降到 0.87 秒。
7. **提交命令与订阅事件流分开。** 命令接口本身幂等（#6 §1），重连不会重复提交工作。
8. **多项目（M3）：一个窗口一条连接，连接属于 host。**
   - 项目范围的请求与命令带 `project`（项目 ID）。host 范围的不带：项目列表与状态、新建项目、归档与取消归档、重试打开、权限模式、额度重试、停止后端。
   - 项目范围的推送带 `project`：事件日志的新条目、Thread 的新序号、运行中 turn 的 item。每个项目的事件序号与 Thread 序号各自独立。
   - Angela 的请求、命令与推送在 `project` 中写 `angela`（M4，data-model.md §10.6）。她的快照与项目的快照形状相同，没有仓库和任务，窗口因此像显示执行者一样显示她。host 的快照带 `angela`：打不开的原因、她等用户处理的条目、是否有 turn 在运行。
   - host 的快照列出各项目的状态与"等你决定"的条目，用于全局汇总（§2）。项目的快照只描述这个项目。
   - 收到 `resync` 时，客户端重新取 host 的快照，以及正在看的项目的快照。

### 4.2 规则

- **每帧最多提交一次更新。** 已完成的历史封存并缓存渲染结果，只有末尾在增长。LibreChat 改为每帧写一次缓存后，单条回复的渲染次数从 5.7 万降到 4200。
- **正在流式输出的那一行始终挂载，滚动只有一个控制者。** 反例：Goose 把已完成气泡变高误判成用户上滚，停止了自动跟随。
- **行卸载时显式清理虚拟化缓存。** 反例：opencode 积累了 37,500 个脱离页面的 DOM 节点。
- **数据接收不绑定 `requestAnimationFrame`。** Electron 窗口在后台时会被降频；接收在普通消息处理中完成，只有渲染走动画帧。
- **虚拟化下的选择与复制：** 选区两端所在的行保持挂载；复制取源 Markdown 而不是 DOM；每个块提供复制按钮。

## 5. 性能基线

CI 中固定运行合成场景（参照 OpenHands 的 `BENCH_MESSAGES` 与 Goose 的 401 条消息测试）：

- 2000 条以上事件的会话打开与重放；
- 多个 agent 同时流式输出；
- 长对话中的输入延迟、滚动与会话切换；
- 单条十万行输出、未闭合的 Markdown；
- GUI 断线、重载、暂停消费后的重新同步。

测量输入延迟、主线程停顿、内存、状态滞后与重新同步情况。先建立基线，再据结果确定预算（#6 §5）。

框架、场景与参考数据见 [perf-baseline.md](perf-baseline.md)。CI 在每次推送到 main 时，在 Windows 和 Ubuntu 上各运行一次 `npm run bench`，只记录，不设门槛。本地不运行，看 CI 的 bench 摘要（[AGENTS.md](../AGENTS.md)）。

## 7. 现在的实现

本节写现在的样子。按时间的修改记录在 git 历史和相关 issue 中。

### 7.1 接口

后端在 `/gui` 提供 WebSocket，与 MCP 共用一个本机端口。`backend/crates/lobotomyd/src/gui/` 有 5 个文件：

- `mod.rs`：连接与推送；
- `protocol.rs`：推送的消息类型，以及读方法和运行时动作共用的类型化路由声明；
- `view.rs`：读；
- `command.rs`：命令；
- `bindings.rs`：导出 TypeScript 类型，只在 `ts-rs` feature 下编译。

读到的内容由 `lobotomy_core::view` 中带类型的结构体给出。前端的类型由这些 Rust 类型生成，见本节末尾。读走单独的只读连接（data-model.md §1）。

- 请求 `{id, method, params}`。关于项目的请求在 `params.project` 中写明项目 ID；`command` 的参数是 `{name, args, project}`。前端的 `call` 自动带上窗口正在显示的项目。
- host 范围的方法不需要项目：
  - `host`：host 的快照：各项目的登记、打不开的原因、"等你决定"（不含额度受阻）、是否有 turn 在运行；额度受阻的条目；各 harness 的权限模式；`workers.toml` 读不出来的原因；
  - `command` 中的 `create_project`（新建项目，data-model.md §10.4）、`archive_project`、`unarchive_project`、`retry_open`（参数 `project_id`，data-model.md §10.3、§10.4）、`quota_retry`、`set_permission`、`shutdown`。额度重试后，所有项目的调度器都被唤醒。归档要等被中断的 CLI 退出，最长约 30 秒，请求在归档完成后才返回。
- 项目范围的方法：
  - `snapshot`：快照，含"等你决定"的条目；
  - `thread`：对话分页，`before` 往前翻，`after` 补上新内容；
  - `search`：搜索一个 role 的整条 Thread（§7.11）；
  - `task`：任务详情；
  - `blob`：取文件库中的全文；
  - `disk_usage`：保留的原始输出占用的空间（§7.8）；
  - `command`：用户命令（data-model.md §9.2），以及中断、终止残留进程。
- Angela 的方法（`project` 写 `angela`，§3 第 8 条）：`snapshot`、`thread`、`search`、`blob` 与项目的相同；`command` 是关于她的 turn 与消息的命令。另有三个只属于她的读方法：
  - `refs`：按 ID 读出她回复中 `[[quote:…]]` 与 `[[att:…]]` 引用的内容（§2）；
  - `forwards`：用户的每条消息被她转给了哪个项目的哪个 role，附了什么上下文（"已转给 …"）；
  - `ledger`："共识"显示的记录，不含推测。
- 请求写的项目没有打开时，后端以 `unknown_project` 拒绝；写 `angela` 而 Angela 没有打开时，以 `angela_unavailable` 拒绝。
- 推送：
  - 关于项目的推送带 `project`：事件日志的新条目、Thread 有新 item 时的序号、运行中 turn 的 item。任何项目的事件日志有新条目时，窗口重新取 host 的快照，更新列表中的条数；其余只处理正在显示的项目的推送；
  - 本机设置或项目列表改变时的 `host`，客户端重新取 host 的快照和项目的快照；
  - 每 15 秒一次心跳；
  - 客户端落后时的 `resync`。
- 错误带代码：命令被拒时是拒绝的代码；参数无法解析时是 `bad_request`；其他是 `internal`（[#16](https://github.com/vorton-lang/Lobotomy/issues/16)）。

GUI 的 10 个读方法、22 个命令的参数和结果，以及全部 6 种推送的 TypeScript 类型由 Rust 类型通过 ts-rs 生成，保存在 `frontend/src/api/generated.ts`。`api/types.ts` 复用生成类型，只保留展示层别名。`call`、`command` 和 store 的命令函数按方法名推导参数与返回类型，调用方不指定响应类型。core 命令的名称和输出取自 `Command`，注册列表与实际分发共用；其余读方法和运行时动作共用类型化路由声明：实际分发用声明中的参数类型解析请求，并用结果类型约束序列化；生成器从同一声明导出方法关联。

修改相关 Rust 类型后，在 `frontend/` 运行 `npm run api:generate` 并提交生成结果。`npm run api:check` 只检查，不改生成文件；CI 在 Windows 和 Linux 上运行它，再检查前端类型并构建。检查把少量直接构造的真实 Rust DTO 经 serde 序列化得到的样本交给 TypeScript 编译器，覆盖枚举标签、flatten、跳过的字段、null、可省略的输入和任意 JSON 内容。前端另有编译期用例检查错误的方法名、参数和返回类型不能通过。

生成使用显式 `ts-rs` Cargo feature；默认构建不编译 ts-rs。CI 的 Clippy 对默认构建和带 `ts-rs` 的构建各运行一次。生成器固定把大整数映射为 `number`，因为协议的 JSON 数字经 `JSON.parse` 得到的是 JS number；超过安全整数范围仍可能丢精度。几个在 Rust 中是字符串、取值封闭的字段，例如权限模式、role 的种类、谁暂停了任务，用 `ts(type = …)` 生成字面量联合。事件的 `kind` 是字符串，`payload` 是 `unknown`；item 内容、命令记录和其他 `serde_json::Value` 字段保留为任意 JSON。展示代码在使用处缩小类型，不能由此推断所有动态内容都有固定结构。生成类型不提供运行时校验：连接层仍信任后端响应与推送，命令报告等动态视图仍有局部类型断言。

### 7.2 前端的结构

`frontend/src/`，React + Vite，状态用 zustand。

- 按 §3 的规则：重连或 `resync` 后重新取快照；推送只说什么变了，内容按需拉取。
- 组件按 §4.1 的选型。主要组件：项目列表（`ProjectList.tsx`）、「全部」（`Overview.tsx`）、接入仓库（`ConnectRepo.tsx`）、对话（`Thread.tsx`、`ItemView.tsx`）、给 Angela 的输入框（`Composer.tsx`）、任务面板（`TaskPanel.tsx`）、"等你决定"（`Attention.tsx`）、`Workboard.tsx`、`NewTask.tsx`、`Settings.tsx`。
- 窗口显示哪里：启动时只有一个能打开的项目，就显示它；否则显示「全部」。之后保持用户的选择。正在显示的项目关闭或打不开时，回到「全部」。新建项目后显示新项目。
- 切换项目时，窗口清空上一个项目的快照、对话与任务面板。切换前发出的请求，回复到达时如果已经不是这个项目，丢弃。
- item、事件、报告结果都有类型。界面上的说明文字由 `format.ts` 给出，有单元测试：role 的状态、任务的当前情况、命令折叠后的摘要、turn 异常结束的说法（`abnormalEnd`）。role 名和 harness 名都从数据中来，不写死。
- agent 文本中的 HTML 一律作为文本显示。http(s) 与 mailto 链接在系统浏览器中打开。
  - 指向本机文件的链接也能打开，但不运行程序（用户定，为了打开 Angela 给出的本地截图对照链接）。链接目标是 `file:` URL 或绝对路径（`C:\…`、`C:/…`、`</C:/…>`、`/home/…`）时显示为链接，悬停显示路径。点击后，Electron 主进程这样处理：文件夹，以及网页、PDF、图片、Markdown、文本、JSON、CSV 文件，用系统为它们设置的应用打开；其他文件，例如程序和脚本，只在文件夹中选中它；文件不存在时什么都不做。相对路径和其他协议仍只显示文字。
- 构建产物带 CSP，只运行自己的脚本，只连本机后端。

### 7.3 对话

- 主区显示哪个 role，从快照中取：项目中是执行者，「全部」中是 Angela。
- 对话是否跟随最新内容，记在 store 中（`following`）。往上看历史时，新内容不把对话拉到末尾。不在末尾时，对话底部显示「回到最新」；末尾有新内容时，按钮写"有新内容"，并用强调色。点击后回到末尾，恢复跟随。从输入框发送消息后，对话也回到末尾（[#18](https://github.com/vorton-lang/Lobotomy/issues/18)）。
- 同时触发的"加载更早的一页"只发一个请求。
- 运行时的消息默认收起，只显示第一行，点开看全文。任务说明的第一行不带任务 ID，ID 在发给执行者的消息头里。
- turn 正常结束的分隔线只显示时间，不写"turn 正常结束"，也不表示任务完成；悬停可查 turn ID、任务名称和正常结束状态（用户定，ui-ux-plan.md §7 第 1 条，P2 内部词汇降级）。异常结束保留醒目的说明。harness 没有开始的 turn 标为"没能启动"。
- 回复的 item ID 放在悬停提示；工具调用摘要省略 `lobotomy.` 前缀，展开可查完整名称。
- 长输出只显示开头 6 行与结尾 18 行，全文在查看器中打开（§7.9）。输出块自身不滚动，只有对话与任务面板滚动。
- 命令卡片折叠时只显示命令的第一行（最多 120 个字符）和总行数、字符数。展开后显示开头和结尾，全文在查看器中打开（[#14](https://github.com/vorton-lang/Lobotomy/issues/14)）。
- 报告卡片按后端实际的处理结果显示。没有生效的报告用虚线框、"未生效"标签，并写明原因（#14）。报告了 done 的 turn，如果报告之后还有执行者的回复，报告卡片只显示状态和标题，正文收起在"报告全文"里，因为执行者最后的回复通常重复这些内容（#18）。
- harness 自己的工具（读文件、搜索、任务列表等）既不是命令也不是文件改动，显示为一行折叠的工具调用：工具名和它作用的对象，例如 `Read work.txt`；展开后是输入和返回的内容。工作目录中的路径显示为相对路径。
- Claude 的回复逐块到达，生成过程中就显示已有的文字。Codex 的文本在完成时整块到达，运行中只显示正在执行的命令与已运行时间。
- Markdown 在 worker 中用 marked 解析。生成中的 item 只对最后一块用 `remend` 临时补齐未闭合的语法；围栏还没闭合时，最后一块从围栏开头算起。完成的 item 按原文解析。`remend` 关掉了会改变完整文本含义的几项：不补 `$$`（前端不渲染数学公式），也不转义单个 `~` 和列表项开头的 `>`，让生成中与完成后的显示一致。补齐的内容不写回源文本；补过的结果单独缓存，没补过的结果与完成后相同，item 完成时直接显示，不先闪一下原文。过期的 worker 回复不覆盖新的结果。超过大小上限时显示纯文本。与 §4.1 的差距见 §7.14。

### 7.4 任务面板

- 任务面板是窗口中的一个区域（region），不是对话框：打开时，对话和右栏仍可使用。建任务后，打开的任务面板关闭，让主区的对话露出来；之前的任务仍可从 Workboard 打开。
- 顶部用一行说明任务现在处于哪一轮、在等什么（[#13](https://github.com/vorton-lang/Lobotomy/issues/13)）。
- 面板显示 worker 的交付：PR 链接、交付版本上各项检查的结果，以及 agent 的交付说明（tech-plan.md §7 第 8 组）。
- 面板不按轮显示交付说明：worker 的任务没有后端本地 attempt 的 done 报告（#86，用户定）。
- 任务记录按时间排成一列：执行轮、用户的决定、完成条件的修改。没有投递的消息也写在记录中。
- 验收时，如果用户发给这个任务的消息还没投递，"验收"按钮换成一块提示，列出这些消息，并给出「退回并交给执行者…」和「验收，不再投递这些消息」（data-model.md §4.2，#14）。
- 面板中没有验证详情、改动区与试用，因为没有私有存储（[#86](https://github.com/vorton-lang/Lobotomy/issues/86)，用户定）。

### 7.5 等你决定

- 条目由后端计算，与登记 turn 时的停下规则相同。
- 执行中的任务没有人推动时也列入（#13）：执行者的 turn 正常结束，但没有报告 done，也没有提问；收件箱为空，没有运行中的 turn，也没有停下。这个 turn 中有 Lobotomy 工具调用没有生成命令记录时，附上调用的错误，例如 Codex 拒绝了 `org_report`。
- 用户回答执行者的问题后，问题卡片立即消失，计数不再包括它。执行者再次提问时，问题重新出现（[#17](https://github.com/vorton-lang/Lobotomy/issues/17)，data-model.md §3.5）。
- 等验收的卡片注明还有几条消息没有投递（#14）。
- turn 因权限模式不被允许而没能启动时，卡片说明原因，原始错误默认收起。当前是完全放开时，卡片提供「改用自动审批并继续」（harness-adapter.md §1.9）。卡片只知道现在的设置，不知道失败时用的是哪种：现在不是完全放开时，卡片不点名当时的模式，写明现在的设置，以及继续时按它重新启动（实现时的选择，#94）。
- harness 没有开始的 turn，卡片注明"没有收到那次的内容，继续时会原样重新发送"（data-model.md §3.4）。
- worker 停下等回复时，卡片里的回复写明这次停下，只有第一条回复让它继续；Angela 先回复了，用户的这条被拒，提示里写明谁在什么时候回复的（worker-interface.md §3）。卡片因此消失时，写了一半的回复留作一张小卡，给出「作为普通消息发送」和「丢弃」（用户定）。普通消息排到 worker 的下一个 turn。
- 卡片按内容取 key，不按位置。一张卡片处理掉后，其他卡片里写到一半的回复和打开的弹窗不受影响（#16）。
- 窗口标题与托盘上显示所有项目的条数之和，加上 Angela 的条目和"本机"的额度受阻（data-model.md §10.5）。项目中的右侧栏只显示这个项目的条目，包括它用到的额度域。

### 7.6 Workboard

- worker 的角色行按它各任务的 attempt 状态写："在做 N 件""N 件停下等你""N 件等你验收"，都没有时是"空闲"。worker 的 turn 在 worker 宿主中运行，项目里看不到，下面关于 turn 的几种说法只适用于在后端运行的 role。
- 角色行显示 role 的当前活动，以及它使用的 harness。回复排队时显示"回复在排队，下一个 turn 交给它"；回复绑定后显示"即将开始 turn"，然后是"正在跑 turn"（#17）。
- 任务行是按钮，可以用键盘打开任务面板。

### 7.7 输入与表单

- 写到一半的文字按所在位置存在 store 中，切换项目、「全部」或设置时保留。这些位置包括：给 Angela 的输入框、"等你决定"卡片中的回复、新建任务、退回理由、修改完成条件。关掉对话框也保留；按「取消」或提交成功后清空。
- 新建任务和发送消息在请求返回前禁用按钮。同一份草稿用同一个请求 ID，成功后才换新的。连按两次只执行一次（#16）。
- 带版本检查的表单（完成条件）发送打开时的版本。其间另一个窗口保存了新版本时，后端拒绝这次保存，不覆盖。验收发送面板上显示的完成条件版本（#16）。
- 项目页没有输入框（§2）。还没投递的消息在等验收的卡片和任务面板中提示（§7.4、§7.5，#14）。

### 7.8 设置

设置是单独的页面（用户定），自己管理要显示哪一页，不随窗口当前显示的项目或「全部」改变内容。

- ⚙ 打开设置页，它取代窗口的主体；「返回」（带返回箭头图标）或 Esc 关闭，窗口回到原来的位置。再次打开时显示上次看的那一页。
- 布局参考 GitHub Primer 的设置模式：左侧是设置自己的导航，右侧每项一行，左边是名称和一句说明，右边是控件。导航分组：
  - **本机**：
    - **权限**：每个 harness 一行，完全放开（默认）或自动审批（harness-adapter.md §1.9）。这一页只管 Angela；页面上写明 worker 的权限在 `workers.toml` 中。
    - **Angela**（data-model.md §10.6）：她的 harness，旁边是模型和推理强度两个下拉框（harness-adapter.md §1.2）。turn 运行时不能换 harness（data-model.md §9.2"切换 role 的 harness"）；模型和推理强度随时可以改，下一个 turn 起生效。下拉框列出这个 harness 的模型，第一项"默认"不传参数，用 CLI 的默认值；推理强度列出所选模型支持的档位，已知默认档位时写在"默认"后面。harness 没有列出模型时，两个下拉框换成输入框。换模型时，原来的推理强度新模型不支持，就回到默认。
  - **每个打开的项目**：
    - **常规**：保留的原始输出占用（data-model.md §7.4），打开这一页时才统计；最下面是归档，确认一次后执行（data-model.md §10.4）。常规页不列出角色和它们的 harness、模型（#86，用户定）：项目的执行者是 worker，这些写在 `workers.toml` 中（tech-plan.md §7 第 7 组）。
- 设置页自己读取所选项目或 Angela 的快照，命令也发给这个项目，与窗口正在显示什么无关。这个项目有事件时，设置页重新读取。所选项目被归档或打不开时，设置页回到"权限"。
- 保存方式按 Primer 的规则，同一页中不混用：
  - 分段选择（权限、harness）选中即生效。
- 打不开的项目在项目列表中直接归档；已归档的项目在列表末尾取消归档。

### 7.9 弹窗与全文查看器

- 弹窗渲染在页面末尾，不在打开它的组件里，以免从对话的虚拟列表里打开时被对话区域裁掉（[#15](https://github.com/vorton-lang/Lobotomy/issues/15)）。
- 全文查看器打开时获得焦点，使用 CodeMirror 的标准按键（`@codemirror/commands` 的 `defaultKeymap`）：Ctrl+A、Ctrl+C 复制全部文字，包括没有画出来的行；Ctrl+End 到末尾。另有「复制全文」按钮。只读状态下编辑按键不起作用（#15）。

### 7.10 Electron

`frontend/electron/`。按 §1 的方式：主进程启动 `lobotomyd --host-dir <host 目录>`，一个后端管理所有项目；`backend.json` 和 `backend.log` 在 host 目录中。没有项目时，窗口显示接入页：在 Electron 中选择仓库文件夹，在浏览器中输入路径，然后发 `create_project`。之后的项目从列表的「+ 新项目」接入，表单相同。登记了、但打不开的项目，在列表中显示名称和原因。

- 后端同时只启动一次。后端没能启动时，窗口显示原因和「重试」，不一直停在"正在连接…"（#16）。
- 后端每次启动都换一个端口。窗口断线后，每次重连前都向主进程询问后端当前的地址：主进程读取 `backend.json` 并确认能连上。如果后端没有在运行，主进程不会启动它；要重新启动，由用户重开应用。
- 退出时，主进程向后端发停止请求，只认这个请求自己的回复。

### 7.11 搜索

在主窗口按 Ctrl+F，搜索主区 role 的整条 Thread。

- **后端**：用 SQLite 逐条比对，ASCII 字母不分大小写。搜索的内容：
  - item 的文本、命令及其输出、搜索词、错误；
  - Lobotomy 工具调用记录的标题、正文与问题；
  - 消息，包括排队中的。

  移入文件库的大字段只搜它的开头和结尾，也就是对话里显示的部分。最多返回最近的 1000 个匹配。
- **前端**：
  - 从最新的匹配开始。Enter 往更早走，Shift+Enter 往更新走。
  - 跳到一个匹配时，先把它所在的分页加载出来，再滚过去。
  - 高亮用 CSS Custom Highlight API，不改动行的 DOM。当前匹配所在行里，收起的部分如果包含匹配，就展开。
  - 打开搜索时关闭任务面板。
- **限制**：
  - 跨元素的匹配不标出，例如一半在粗体里。
  - 长输出中间被省略的部分里的匹配，计入结果但看不到，要在查看器中找。
  - 任务面板里的内容不在搜索范围内。

### 7.12 运行（从源码）

1. `cd backend && cargo build -p lobotomyd`
2. `cd frontend && npm install && npm run app`。第一次启动时选择仓库。

开发时可以用 `npm run dev` 加浏览器，地址中带 `?backend=ws://127.0.0.1:<端口>/gui&token=<token>`。

### 7.13 测试

- vitest 测试：任务记录的时间顺序，长文本的截取，回复的预览，问题与回复的区分（#17），异常结束的名称，卡片的 key；流式 Markdown 的补齐与完成后的切换，本地文件的链接；乱序返回的快照和 Thread 读请求不覆盖较新的状态（#28、#85）。

  - 模拟的 WebSocket 驱动真实前端：测界面行为，每个约一秒，结果稳定。

    - `projects.spec.ts`：内部用语退居次要，异常结束仍然可见；设置是单独的一页，在「全部」和项目中都能打开（#51）；从设置归档时先确认。
- 后端的 GUI 接口测试（`lobotomyd/tests/gui.rs`）覆盖：停止后端，以及停止时怎样处理仍连着的客户端、断线后已接收的请求和超时的请求。停止后数据目录的锁释放，由后端测试覆盖。没有报告的 turn 等用户的消息，不响应中断的 CLI 在宽限期后连同进程树结束，退出时不等中断直接结束 CLI，由 worker 宿主的测试覆盖（`worker/tests/runner.rs`）。

### 7.14 限制

- 没有安装包，Electron 从源码树找后端。
- 窗口窄于 760 像素时不显示项目列表，把宽度留给正在显示的项目。
- Inspector（§2）未实现，列入 roadmap 待排。
- Windows 上由 Electron 拉起的后端会继承 Electron 的标准输出句柄。正常从桌面启动时没有影响；Playwright 因此要先停后端才能关闭应用。

与 §3、§4.1 的差距（都未实现，列入 roadmap 待排）：

- 没有按 agent 分别节流（§3 第 3 条）。后端每 100ms 查看一次每个项目与 Angela 的事件日志和运行中的 turn，有变化就推送给所有窗口，不区分正在看的 agent 和后台的 agent。
- 流式 Markdown 没有按块解析：每次更新都把整条文本交给 worker 重新解析。未闭合围栏中的代码也会高亮。
- Shiki 没有自己的 LRU 缓存：每次解析都重新高亮文本中的所有代码块。主线程按整条文本缓存最近 500 个渲染结果；输入大小上限已有，超过 5 万个字符的代码不高亮。
- 全文查看器没有把 ANSI 颜色转为装饰。

### 7.15 视觉基础

界面改进专项的 P0（[ui-ux-plan.md](ui-ux-plan.md) §4）。

- `styles.css` 开头的两个 `:root` 块定义全部颜色：亮色一套，`prefers-color-scheme: dark` 一套。规则中只用语义变量：背景（`--bg`、侧栏 `--bg-rail`、卡片与输入框 `--panel`、`--sunken`）、悬停与按下、边线、文字（`--text`、`--muted`）、强调色，以及四种状态（运行 `--run`、等你 `--wait`、失败 `--fail`、完成 `--done`），每种都有文字色、实色、浅底与边线。另有字号（12 / 13 / 14 / 16 / 20）、圆角、阴影与动效时长的变量；减弱动效时，时长为 0。
- 颜色的规则：两个 `:root` 块之外没有颜色字面量；每个颜色都有暗色的值；文字与它所在的底色对比度不低于 4.5:1，焦点环与状态标记不低于 3:1，亮暗两套都要满足。现在没有自动检查。
- 字体只用系统字体：界面先用 Segoe UI Variable / Segoe UI 显示西文，中文落到微软雅黑 UI，Linux 上用 Noto；等宽字体是 Cascadia Mono。消息与卡片的正文打开 `text-autospace`，代码中关闭。
- 控件按桌面应用的习惯：按钮与列表行是箭头光标，悬停时换底色，文字不可选中；键盘焦点有统一的焦点环。在 Electron 中，窗口失去焦点时，项目列表与设置导航中的选中项变淡。
- 折叠块的箭头由 CSS 画出，展开时转动。图标用 lucide-react，按钮中只有图标时，按钮写 `aria-label`。
- Electron 的窗口在页面第一次绘制后才显示，窗口背景色与页面的 `--bg` 相同，不先闪白。
- **角色与状态**（P1，`components/Status.tsx`）：
  - 每个 role 一个颜色：Angela、Malkuth、Binah、Yesod 各有固定的颜色，其他名字按名字算出 6 色之一（`format.ts` 的 `roleHue`）。头像是名字的首字母加这个颜色。Workboard 的角色行、对话中 agent 与 Angela 消息的署名都带头像，名字用这个颜色。
  - 状态有 5 种外观（`format.ts` 的 `Look`）：运行是会脉冲的实心点，等你是琥珀色空心环，失败是三角，完成是对勾，静止是灰点；减弱动效时不脉冲。短的状态（任务阶段、"打不开"）是带底色的标签，句子（角色在做什么）是标记加文字。任务阶段、角色活动、turn 结局各自映射到一种外观，有单元测试。
  - Workboard 中，进行中的任务排在它的执行者下面，缩进到头像之后。
  - 运行中的 turn 两分钟以上没有新条目时，Workboard 的角色行与对话中这个 turn 的最后一条下面写"N 分钟没有新输出"。有命令或工具还在运行时不写，它们自己显示已运行的时间。时间按窗口看到条目变化的时刻算；第一次看到这个 turn 时，按它最新一个条目的开始时间算。这一行只陈述事实，不判断 turn 是否卡住。
- 截图场景：`e2e/screenshots-mocked.spec.ts` 用模拟的后端截「全部」、项目、任务面板和窄窗口，亮暗各一张。它只在设置了 `SCREENSHOT_DIR` 时运行，用于审阅，不是测试。
