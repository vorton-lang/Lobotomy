# 前端

> Status: 设计决定 v0.2（2026-10-03）
> v0.2 按 [#7 的讨论补充](https://github.com/vorton-lang/Lobotomy/issues/7#issuecomment-5953401457)修订：流式 partial 只在后端内存中，不做 checkpoint；GUI 重连后的补显示与后端崩溃分开描述。
> 依据：[#6](https://github.com/vorton-lang/Lobotomy/issues/6) §5；对 20 个 agent GUI 产品的调研（issue、PR、源码，见 [research/frontend-survey.md](research/frontend-survey.md)）；本机 Codex / Claude 桌面应用的依赖扫描。

## 0. 原则

- **后端是权威，前端只是投影。** UI 卡顿、重载或重连后，前端从快照加序号重新同步。正确性不依赖 UI 及时消费每个事件（#6 §5）。重新同步只覆盖后端仍在运行的情况，不是后端崩溃恢复（见 §3 第 2 条）。
- **长对话、多路并行流式输出、单条巨量输出是常规负载。** 性能从第一天就设计和测量，不在功能完成后再补。
- **不依赖平台特有行为。** 先在 Windows 上开发，正式发版前修 Linux 问题。

## 1. 形态与进程

```text
Rust 后端（独立进程，常驻） ←── WebSocket ──→ Electron 渲染进程（React + TypeScript）
                                              Electron 主进程：窗口、托盘、系统通知
```

- 渲染进程直接用 WebSocket 连接后端；这个服务也为 role 提供 MCP。Electron 主进程不转发业务数据，保持空闲。浏览器同样可以连接，方便开发调试。
- 关闭窗口不退出，托盘常驻。关闭 GUI 不改变组织的运行意愿（#5）。
- **后端的启动与停止**（用户确认，2026-10-04）：
  1. Electron 启动时，如果项目的后端没在运行，就启动它。后端与 Electron 分离，Electron 崩溃不带走后端。
  2. 后端监听后，在项目数据目录写入 `backend.json`（端口与 pid），正常停止时删除。Electron 据此找到正在运行的后端。
  3. 关闭窗口时，窗口退到托盘，组织照常运行。
  4. 托盘菜单"退出 Lobotomy"按正常停止进行（harness-adapter.md §1.8）：中断正在运行的 turn，等它们退出，然后后端退出。退出 GUI 就是停止组织。
- **GUI 接口的访问控制**（用户确认，2026-10-04）：
  - 后端只监听 `127.0.0.1`。每个 GUI 连接都要带 token。token 在第一次启动时生成，存放在 host 目录（`%LOCALAPPDATA%\Lobotomy\gui-token`），Electron 从那里读取；它不进入 role 与检查命令的环境。
  - 后端校验 `Host` 与 `Origin`，挡住网页的连接。允许的 Origin：没有 Origin、`file://`、本机地址（开发时的 Vite）。
  - 边界：这能挡住网页和误调用，挡不住存心读取 token 文件的 agent。同一 OS 用户下做不到真正的隔离（#6）。不把 token 只放在内存里，是因为那样 GUI 进程重启后连不回仍在运行的后端。
- **通知**：后端按 [manager-actions.md](manager-actions.md) §6 的规则判定，并持久保存通知意图；Electron 主进程用跨平台的 Notification API 投递。GUI 进程不在时意图保留，下次打开时在界面内显示，不补发系统通知。M1 不做系统通知，只在窗口标题与托盘上显示"等你决定"的条数（用户确认，2026-10-04）。
- 先例：Codex 桌面应用就是 Electron 前端加独立的 Rust app-server（JSON-RPC）。

- **主区**是与 Angela 的对话，也是默认焦点。对话中出现收起的附件、"已转给 X"标签、系统提示（`flag_mismatch`、验证失败）、会议卡片，以及 `ask_user` 的问题（可带选项按钮）。
- **右侧栏**从上到下：
  1. **等你决定**：待回答的问题、待确认的对外操作、会议提议。只有这一块需要用户动手。
  2. **Workboard**：见 [roles-and-tasks.md](roles-and-tasks.md) §3。
  3. **共识**：默认收起，只显示条数，点开可编辑。
- **顶栏**：仓库名与预览最近一次更新的时间。
- **会议进行中**：主区换成会议记录，顶部显示参会者和"结束会议"，右侧栏不变。
- **Inspector**：点击角色名从右侧滑出。

  | 标签页 | 内容 |
  |---|---|
  | 状态 | harness / 模型、会话 ID 与时长、上下文用量、缓存命中、额度、当前任务与执行轮、语义检查点、新出现的工具提示 |
  | 输出 | 该 role 的全部产出，包括未呈现给用户的 |
  | 改动 | 按执行轮列出成果及其相对基线的 diff、采集记录。"撤销这一轮"推迟到 M1 之后（harness-adapter.md §4.1） |
  | 对话 | 一对一直接对话 |
  | 操作 | 继续会话 / 存检查点后开新会话 / 切换模型 / 暂停 / 在官方应用中打开、交还（待排，见 [roadmap.md](roadmap.md)） |

  Angela 的 Inspector 多一项"推测"。
- **role play 只在展示层**：名字，以及每个角色一个标识色或头像。

**M1 的布局**（用户确认，2026-10-04；做出来后按实际效果迭代）：M1 没有 Angela，只有 Malkuth。
- 主区是 Malkuth 的 Thread：用户的消息、它的回复与工具调用、汇报、运行时的消息（例如验证失败）。输入框直接发给 Malkuth。
- 右侧栏照上面的设计：等你决定、Workboard。
- 点开任务，看候选成果的 diff，在那里验收或退回。
- M3 有了 Angela 以后，主区换成与她的对话，Malkuth 的 Thread 移进 Inspector。用户随时可以直接打开它：直接通路是常设的二等入口，不是临时方案（**语义更新**，[#23](https://github.com/vorton-lang/Lobotomy/issues/23)，用户确认，2026-10-09）。

## 3. 后端与前端的协议

1. **数据模型参照 Codex 的 Thread → Turn → Item。** 完成的 item 是权威状态，流式增量只用于实时显示。Turn 就是业务上的 turn（一次 CLI 进程运行），使用同一个 turn_id（[data-model.md](data-model.md) §3）。
2. **增量在 Rust 中合并，永不落库（#7）。**
   - 流式 partial 只保存在后端内存中。后端崩溃时，partial 丢失。实测中只有 Claude 的模型文本会流式到达；Codex 的文本和两家的工具输出都在完成后整块到达（harness-adapter.md §1.4）。工具运行期间，GUI 显示命令与已运行时间。运行时不为未完成的展示输出做 checkpoint；这一条取代 v0.1 的"定期检查点"。
   - 每个 item 在自身完成时写入 SQLite，不等整个 turn 结束。
   - 业务命令发生时立即写入 SQLite，与 CLI turn 是否结束无关。
   - 大内容放在文件中，数据库只保存元数据和引用。
   - 反例：t3code 一条 1 万字回复写出 3024 条 SQLite 事件且越用越卡；Cline 逐片重存快照，数据库涨到 1.66 GB。
3. **按 agent 分别节流。** 正在看的 agent 约每 16ms 推送一次，后台 agent 每 150–400ms 一次；推送状态消息前先发完积压的文本（Kilo）。
4. **每个 Thread 一个单调递增序号**（[data-model.md](data-model.md) §7.6）。
   - 重连时，前端先订阅，再拉取某个序号时刻的快照，然后应用该序号之后的增量。后端仍在运行时，快照包含已合并的当前 partial、已完成的 item 和对应序号（#7）。
   - 重放缓冲有上限，溢出时明确发出"重新拉取快照"信号，绝不悄悄丢弃。反例：Goose 的传输队列溢出后悄悄断开订阅，部分会话从此无法打开。
   - 加心跳与卡死检测，应对悄无声息断掉的 TCP 连接。
5. **通知只说什么变了，不携带内容。** 内容由前端按需拉取。超大输出由后端保存全文，只推送开头、结尾与总大小；用户展开时按行范围拉取。存储方式见 data-model.md §7.3。
6. **打开会话从末尾加载。** 只取最近 N 条，更早的内容在向上滚动时分页加载。Goose 只重放最近 200 条后，加载从 3.85 秒降到 0.87 秒。
7. **提交命令与订阅事件流分开。** 命令接口本身幂等（#6 §1），重连不会重复提交工作。

## 4. 渲染

### 4.1 组件

| 用途 | 选型 | 说明 |
|---|---|---|
| 对话列表虚拟化 | virtua | LobeHub 从 Virtuoso 迁到 virtua，Cherry Studio、Kilo 也在用。备选 TanStack Virtual ≥3.17.6 的 chat 模式 |
| 流式 Markdown | 在 worker 中用 marked 分块，已结束的块封存，未闭合语法用 `remend` 补齐，每条流各自保存解析状态 | 不整套使用 Streamdown：它每次更新都重切整条消息，尾部缓存是全局单例，多路并行流会互相干扰 |
| 代码高亮 | Shiki 放在 worker 中，用 JS 正则引擎，加 LRU 缓存与输入大小上限 | 流式中的代码块先显示纯文本，围栏闭合后再高亮。反例：Kilo 同步调用 Shiki 卡住主线程 2.3 秒 |
| 超大单条输出 | 对话中只显示头尾若干行，加"在查看器中打开"；查看器是只读的 CodeMirror 6，ANSI 颜色在 worker 中转为装饰 | CodeMirror 官方演示可流畅加载数百万行 |
| diff | @pierre/diffs | 自带 worker 池与虚拟化；opencode、t3code 在用 |
| 搜索 | 自建 Ctrl+F：后端在 SQLite 中搜索整条 Thread，前端加载到匹配所在的分页，滚动过去，用 CSS Custom Highlight API 标出。原设计是在 worker 中搜索前端的数据模型；前端只有已加载的分页，所以改由后端搜索（**语义更新**，2026-10-04） | 虚拟化后浏览器查找搜不到未挂载的内容。Claude 桌面应用也自带查找窗口和对话搜索 worker |
| 状态订阅 | 按行用选择器订阅（zustand 一类），展开/收起状态放在行外 | OpenHands 改用选择器后输入延迟从 171ms 降到 22ms |

xterm.js 只用于实时终端，v1 不需要。

### 4.2 规则

- **每帧最多提交一次更新。** 已完成的历史封存并缓存渲染结果，只有末尾在增长。LibreChat 改为每帧写一次缓存后，单条回复的渲染次数从 5.7 万降到 4200。
- **正在流式输出的那一行始终挂载，滚动只有一个控制者。** 反例：Goose 把已完成气泡变高误判成用户上滚，停止了自动跟随。
- **行卸载时显式清理虚拟化缓存。** 反例：opencode 积累了 37,500 个脱离页面的 DOM 节点。
- **数据接收不绑定 `requestAnimationFrame`。** Electron 窗口在后台时会被降频；接收在普通消息处理中完成，只有渲染走动画帧。
- **虚拟化下的选择与复制：** 选区两端所在的行保持挂载；复制取源 Markdown 而不是 DOM；每个块提供复制按钮。

## 5. 性能基线

CI 中固定运行合成场景（参照 OpenHands 的 `BENCH_MESSAGES` 与 Goose 的 401 条消息测试）：

- 2000 条以上事件的会话打开与重放；
- 多个 agent 同时流式输出；
- 长对话中的输入延迟、滚动与会话切换；
- 单条十万行输出、未闭合的 Markdown；
- GUI 断线、重载、暂停消费后的重新同步。

测量输入延迟、主线程停顿、内存、状态滞后与重新同步情况。先建立基线，再据结果确定预算（#6 §5）。

M1 的框架、场景与第一份参考数据见 [perf-baseline.md](perf-baseline.md)。本机运行 `npm run bench`；CI 在每次推送到 main 时，在 Windows 和 Ubuntu 上各运行一次，只记录，不设门槛。

## 7. M1 的实现（2026-10-04，第 4 个增量）

**接口**：后端在 `/gui` 提供 WebSocket，与 MCP 共用一个本机端口（`backend/crates/lobotomyd/src/gui/`）。返回内容的结构由 `lobotomy_core::view` 中带类型的结构体定义，前端的 `api/types.ts` 与之对应。

- 请求 `{id, method, params}`，方法有：
  - `snapshot`：快照，含"等你决定"的条目；
  - `thread`：对话分页，`before` 往前翻，`after` 补上新内容；
  - `task`：任务详情；
  - `diff`：两个提交之间的文件改动；
  - `blob`：取文件库中的全文；
  - `command`：用户命令，以及接入、中断、终止残留进程、额度重试、重试出错的工作、修改 harness 的权限模式、停止后端。
- 推送：
  - 事件日志的新条目；
  - Thread 有新 item 时的序号；
  - 运行中 turn 的 item；
  - 本机设置改变时的 `host`，客户端重新取快照；
  - 每 15 秒一次心跳；
  - 客户端落后时的 `resync`。
- "等你决定"的条目由后端计算，与登记 turn 时的停下规则相同。最近一次采集还没完成时，role 是在等运行时，不列入。
- 执行中的任务没有人推动时也列入（#13）：执行者的 turn 正常结束，但没有报告 done，也没有提问；收件箱为空，没有运行中的 turn，也没有停下或待采集。M1 没有 Manager，只有用户能让它继续。这个 turn 中有 Lobotomy 工具调用没有生成命令记录时，附上调用的错误，例如 Codex 拒绝了 `org_report`。

**前端**：`frontend/`，React + Vite，状态用 zustand。
- 按 §3 的规则：重连或 `resync` 后重新取快照；推送只说什么变了，内容按需拉取。
- 组件按 §4.1 的选型。
- agent 文本中的 HTML 一律作为文本显示，链接只打开 http(s) 与 mailto，并在系统浏览器中打开。
- 构建产物带 CSP，只运行自己的脚本，只连本机后端。

**实测后的调整**（#13，2026-10-04）：
- diff 的结果带着它所对应的提交范围。范围变了、新结果还没到时，显示"正在计算"，不显示上一个范围的内容。
- 任务面板顶部用一行说明任务现在处于哪一轮、在等什么。上一轮的验证与候选成果仍然显示，但标为"上一轮"，不当作当前结果。
- 改动区按轮选择：最新一轮已验证的候选成果、它的候选成果、它最近一次采集；这一轮还什么都没有时，显示上一轮的候选成果并标明。
- 任务记录按时间排成一列：执行轮、验证、用户的决定、发布、完成条件的修改。
- 建任务后关闭打开的任务面板，让主区的对话露出来；之前的任务仍可从 Workboard 打开。
- turn 正常结束显示为"turn 正常结束"，不再显示"已完成"，避免与任务完成混淆。
- 主区中运行时的消息默认收起，只显示第一行，点开看全文。任务说明的第一行不再带任务 ID，ID 在发给执行者的消息头里。
- 长输出只显示开头 6 行与结尾 18 行，全文在查看器中打开。输出块自身不再滚动，只有对话与任务面板滚动。

**实际使用后的调整**（#14，2026-10-04）：
- 任务面板：验收时，如果你发给这个任务的消息还没投递，原来的"验收"按钮换成一块提示，列出这些消息，并给出「退回并交给执行者…」和「验收，不再投递这些消息」。等你验收的卡片也会注明还有几条未投递。任务记录写明哪些消息没有投递。
- "等你决定"新增"任务之外的改动"：列出改了哪些文件，可以查看改动、丢弃，或建成任务（data-model.md §4.2；harness-adapter.md §3）。
- 报告卡片按后端实际的处理结果显示。没有生效的报告用虚线框、"未生效"标签，并写明原因，不再显示成绿色的"完成"。
- 命令卡片折叠时只显示命令的第一行（最多 120 个字符）和总行数、字符数。完整命令展开后显示开头和结尾，全文在查看器中打开。

**实际使用后的调整**（#15，2026-10-05）：
- 弹窗渲染在页面末尾，不在打开它的组件里。原来从对话的虚拟列表里打开时，弹窗的位置和高度跟着来源行变化，靠下的行打开的全文窗口被对话区域裁掉。
- 全文查看器打开时获得焦点，使用 CodeMirror 的标准按键（`@codemirror/commands` 的 `defaultKeymap`）：Ctrl+A、Ctrl+C 复制全部文字，包括没有画出来的行；Ctrl+End 到末尾。另有「复制全文」按钮。只读状态下编辑按键不起作用。
- 验证和验收阶段，输入框的提示按 #14 的规则说明：消息先排队，任务回到执行时投递；直接验收则不再投递。

**重构第一轮**（[#16](https://github.com/vorton-lang/Lobotomy/issues/16)，2026-10-05）：
- 新建任务和发送消息在请求返回前禁用按钮；同一份草稿用同一个请求 ID，成功后才换新的。连按两次只执行一次。
- "等你决定"的卡片按内容取 key，不按位置。一张卡片处理掉后，其他卡片里写到一半的回复和打开的弹窗不受影响。
- 带版本检查的表单（项目设置、完成条件）发送打开时的版本。其间另一个窗口保存了新版本时，后端拒绝这次保存，不覆盖；项目设置会提示已有新版本。验收发送面板上显示的完成条件版本。
- turn 异常结束的说法由 `format.ts` 的 `abnormalEnd` 统一给出，对话与卡片一致。
- Electron：同一项目同时只启动一次后端；后端没能启动时，窗口显示原因和「重试」，不再一直停在"正在连接…"。退出时只认 shutdown 请求自己的回复。

**重构第二轮**（[#16](https://github.com/vorton-lang/Lobotomy/issues/16)，2026-10-05）：⚙ 设置新增"存储"，显示保留的原始输出有多少文件、占多少空间（data-model.md §7.4）。打开设置时才统计，不随快照计算。原始输出目前不自动删除。

**重构第三轮**（[#16](https://github.com/vorton-lang/Lobotomy/issues/16)，2026-10-09）：
- 后端：
  - GUI 读到的内容由 `lobotomy_core::view` 给出：快照的数据库部分、"等你决定"的计算、对话分页、搜索、任务详情、事件日志。原来按数据库列名直接输出的任务详情，改为带类型的结构体。
  - `lobotomyd/src/gui/` 分三部分：连接与推送（`mod.rs`）、读（`view.rs`）、命令（`command.rs`）。
  - 读走单独的只读连接（data-model.md §1）。
  - 接口变化：任务详情中检查记录的 `timed_out` 由 0/1 改为布尔值；验证带上 `created_at`、`finished_at`；执行轮与消息带上全部字段。
- 前端：
  - 主区显示哪个 role，从快照中取：M1 中是唯一的执行者。界面文字中的 role 名和 harness 名都从数据中来，不再写死。
  - `Sidebar.tsx` 拆成"等你决定"的卡片（`Attention.tsx`）、`Workboard.tsx` 和 `NewTask.tsx`。
  - item、事件、报告结果有了类型。role 的状态、输入框的提示、任务的当前情况、检查结果、命令折叠后的摘要等文字，由 `format.ts` 给出，有单元测试。
  - 任务面板是窗口中的一个区域（region），不再标为对话框：打开时，对话和右栏仍可使用。Workboard 中的任务行是按钮，可以用键盘打开。
  - 对话是否跟随最新内容，记在 store 中（`following`）。同时触发的"加载更早的一页"只发一个请求。
  - 重复的样式合并：阶段标签与其他小标签共用 `badge`；未投递消息的提示框沿用警示卡片的样式。

**实际使用后的调整**（[#17](https://github.com/vorton-lang/Lobotomy/issues/17)、[#18](https://github.com/vorton-lang/Lobotomy/issues/18)，2026-10-09）：
- 回答执行者的问题后，问题卡片立即消失，"等你决定"的计数不再包括它。回复排队时，Workboard 的 role 行显示"你的回复在排队，下一个 turn 交给它"。回复绑定后，role 行显示"即将开始 turn"，然后是"正在跑 turn"。执行者再次提问时，问题重新出现（data-model.md §9.2）。
- 报告了 done 的 turn，如果报告之后还有执行者的回复，报告卡片只显示状态和标题，正文收起在"报告全文"里。执行者最后的回复通常重复这些内容。
- 任务面板中的任务不是执行者当前的任务时，面板顶部写明执行者现在做的任务，并给出「查看当前任务」。面板不自动切换。
- 不在对话末尾时，对话底部显示「回到最新」。末尾有新内容时，按钮写"有新内容"，并用强调色。点击后回到末尾，恢复跟随。从输入框发送消息后，对话也回到末尾。

**接入 Claude**（M2，2026-10-10）：
- ⚙ 设置新增"角色 · 本项目"：每个角色一个 harness 选择，选中即生效（data-model.md §9.2"切换 role 的 harness"）。turn 运行时不能切换。权限一节多出 Claude 一组。
- Workboard 的角色行显示它当前使用的 harness。
- harness 自己的工具（读文件、搜索、任务列表等），既不是命令也不是文件改动的，显示为一行折叠的工具调用：工具名和它作用的对象，例如 `Read work.txt`；展开后是输入和返回的内容。工作目录中的路径显示为相对路径。
- Claude 的回复逐块到达，生成过程中就显示已有的文字。

**权限模式**（2026-10-04，harness-adapter.md §1.9）：
- ⚙ 设置的第一节是"权限"，每个 harness 一组：完全放开（默认）或自动审批。这一节属于本机，所有项目共用，选中即生效，不随项目设置的版本保存。M2 接入 Claude 后，Claude 单独一组。
- turn 因权限模式不被允许而没能启动时，"等你决定"卡片说明原因，原始错误默认收起。当前是完全放开时，卡片提供「改用自动审批并继续」。
- harness 没有开始的 turn，卡片注明"没有收到那次的内容，继续时会原样重新发送"。Thread 中这个 turn 标为"没能启动"。

**搜索**（第 5 个增量）：在主窗口按 Ctrl+F，搜索 Malkuth 的整条 Thread。
- **后端**：用 SQLite 逐条比对，ASCII 字母不分大小写。搜索的内容：
  - item 的文本、命令及其输出、搜索词、错误；
  - Lobotomy 工具调用记录的标题、正文与问题；
  - 消息，包括排队中的。
  
  移入文件库的大字段只搜它的开头和结尾，也就是对话里显示的部分。最多返回最近的 1000 个匹配。
- **前端**：
  - 从最新的匹配开始。Enter 往更早走，Shift+Enter 往更新走。
  - 跳到一个匹配时，先把它所在的分页加载出来，再滚过去。
  - 高亮用 CSS Custom Highlight API，不改动行的 DOM。当前匹配所在行里，收起的部分如果包含匹配，就展开。
  - 打开搜索时关闭任务面板。
- **限制**：
  - 跨元素的匹配不标出，例如一半在粗体里。
  - 长输出中间被省略的部分里的匹配，计入结果但看不到，要在查看器中找。
  - 任务面板里的内容不在搜索范围内。

**Electron**：`frontend/electron/`，按 §1 的启停方式实现。项目目录记在 host 目录的 `gui.json` 中。
- 后端每次启动都换一个端口。窗口断线后，每次重连前都向主进程询问后端当前的地址：主进程读取 `backend.json` 并确认能连上。如果后端没有在运行，主进程不会启动它；要重新启动，由用户重开应用。

**运行（从源码）**：

1. `cd backend && cargo build -p lobotomyd`
2. `cd frontend && npm install && npm run app`。第一次启动时选择仓库。

开发时可以用 `npm run dev` 加浏览器，地址中带 `?backend=ws://127.0.0.1:<端口>/gui&token=<token>`。

**测试**：

完整测试的耗时测量、调度方式与复现命令见 [test-performance.md](test-performance.md)。

- vitest 测试对话分行（含完成报告的收起）、任务记录的时间顺序、改动区按轮的选择、长输出的截取，以及 `format.ts` 给出的文字：role 的状态、输入框的提示、检查结果、命令摘要、报告是否生效；
- Playwright 用本机 Edge，驱动真实后端与假 Codex。每个测试启动自己的后端，测试之间没有顺序依赖（#16）：
  - 走完建任务、执行、验证、看 diff、验收、用户仓库出现文件；
  - 任务面板保持打开，经过一次退回，新候选验证期间与通过后都显示它自己的 diff（#13）；
  - turn 失败后继续；继续的 turn 没有报告时出现"还没有完成"，在任务面板放弃；
  - 受管 Codex 不允许完全放开：卡片说明原因，「改用自动审批并继续」后任务说明重新送达、任务走到验收；在设置中改回完全放开；
  - Ctrl+F 搜到最新一页之外的内容：加载、滚动到那里并高亮；
  - 300 条 item 的对话，CPU 降速 4 倍时一路滚到开头，每一页都能加载上来（CI 中的性能基线发现过对话停在顶部）；
  - 执行者交出候选成果后才轮到投递的消息：验收时列出，选择不再投递后任务完成（#14）；
  - 任务之外的改动：报告显示为未生效，建成任务后验收，改动进入用户仓库（#14）；
  - 400 行的 heredoc 命令折叠时高度有限，搜索能找到它的最后一行并展开（#14）；
  - 执行者提问，用户在卡片中回答：卡片立即消失；执行者处理回复期间，"等你决定"为空（#17）；
  - 验收后下一个任务开始：已完成任务的面板写明当前任务，并能切换过去（#18）；
  - 往上看历史时不被拉到末尾；新任务产生内容时出现「有新内容 · 回到最新」，点击后回到末尾；被最后回复重复的完成报告，正文收起（#18）；
  - 在设置中把 Malkuth 切换到 Claude，任务在假 Claude 上走到验收；对话中显示文件改动、折叠的工具调用和报告（M2）；
- 后端测试覆盖搜索的范围与顺序；
- Electron 外壳测试覆盖：没有项目时的接入、启动后端、退出时停止组织；
- Electron 被强制结束后后端仍在运行：手动验证过（Windows）。
- 重连与重新同步：
  - Electron 测试覆盖后端换端口重启后窗口自动重连；
  - 后端测试覆盖读得慢的客户端收到 `resync`；
  - 性能基线测量后端重启后 GUI 恢复的时间。

**限制**：
- 没有安装包，Electron 从源码树找后端。
- Inspector 还没有做：M1 只有一个 role，它的 Thread 就在主区。
- Codex 的文本在完成时整块到达，运行中只显示正在执行的命令与已运行时间。
- Windows 上由 Electron 拉起的后端会继承 Electron 的标准输出句柄。正常从桌面启动时没有影响；Playwright 因此要先停后端才能关闭应用。
