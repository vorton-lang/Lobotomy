# 外部系统 adapter

本文是外部系统接入的接口设计。已定和待决的事项列在 §9。它不是实现规格，现在没有实现。

依据：
- 2026-10-18 的四路资料调研：同类 personal agent 怎样接入外部系统；用户的痛点；本机开源应用的接入路径与合规；代表用户行动时的安全与授权。资料调研没有做实测。
- worker 协议的形态与约定（[worker-interface.md](worker-interface.md)）。

术语：
- **外部系统**：网盘、邮件、文档这类用户在 Lobotomy 之外使用的服务。
- **外部系统 adapter**（下文简称 adapter）：把一个外部系统的能力交给后端的程序。它和 harness adapter（[harness-adapter.md](harness-adapter.md)）不是一回事。
- **来源**：adapter 的一个运行实例，对应外部系统的一个账户。
- **后端**：Lobotomy 的后端进程，协议中 adapter 的对端。

## 0. 前提（用户定）

1. **内核不开放插件。** 扩展只在两处：worker（worker-interface.md）和外部系统 adapter。
2. **凭据不进后端。** 凭据、登录和同步都由 adapter 负责，adapter 内部怎么设计不限。理由：凭据放在后端，接 10 个来源就要管 10 份凭据。
3. **adapter 只用一个协议把能力交给后端。** Angela 只经后端的转发使用这些能力。后端给 Angela 的工具可以和 adapter 交给后端的操作不一样。
4. **以读为主，写一律要用户授权。** 理由：用户自己用到写的频次低，逐次授权可以接受。
5. **一个来源对应一个账户，同一个 adapter 程序可以启动多个实例。** 理由：调研中证据最多的痛点是一个连接器连不了多个账户，例如 [claude-code#27302](https://github.com/anthropics/claude-code/issues/27302)（2026-10-18 时 415 👍）。

## 1. 分层

```
Angela
   │  后端的 MCP：固定的几个工具（§6）
后端（授权检查、记入图、文件库、通知）
   │  adapter 协议：跨进程，有版本，带能力声明
adapter 实例 = 一个来源 ── 外部系统
```

| 谁 | 负责 | 看不到 |
|---|---|---|
| 后端 | 启动和管理 adapter 实例；检查写操作的授权；把结果记入图和文件库；把能力转给 Angela；登录失效时通知用户 | 凭据；外部系统的 API |
| adapter | 凭据与登录；调用外部系统；声明每个操作是读还是写；把大内容传进文件库 | 授权；Angela；图 |

worker 不直接使用 adapter，因为 Lobotomy 的 MCP 只给 Angela 用（worker-interface.md §1）。worker 的任务需要外部材料时怎么办，列为待决（§9）。

## 2. 配置与生命周期

- 来源写在 host 目录的 `adapters.toml` 中，每个条目一个来源：来源 ID、显示名、启动命令与参数、环境变量。同一个程序配几个条目，就启动几个实例。
- 后端给每个实例一个数据目录 `<host 目录>/adapters/<来源 ID>/`，启动时作为参数传给它。adapter 把凭据和缓存放在这里，后端不读。同一程序的各个实例的数据目录不同，adapter 不能假定自己是唯一的实例。
- 进程经后端统一的启动函数启动（harness-adapter.md §1.8），随后端退出。
- 实例退出或崩溃时，后端把这个来源标为"已退出"，在界面上显示，不自动重启。用户可以在设置中重启它；后端下次启动时也会启动它（用户定）。依据：AGENTS.md 原则 4，恢复先靠手动。

## 3. 能力声明（`hello`）

`hello` 返回：
- 协议版本。
- 来源的种类与显示信息，例如 `google-drive` 和账户名。
- 操作清单。每个操作包括：
  - 名称；
  - 给 agent 看的说明；
  - 参数的 JSON Schema；
  - 结果说明；
  - `effect`：必填，取 `read` 或 `write`（用户定）。有操作缺了它或取别的值时，后端拒绝整个能力声明，把这个来源标为 `error` 并写明原因（实现时的选择）。

后端按声明行事，未声明的能力视为不支持，与 worker 协议 §8 相同。后端不核实 `effect` 是否如实：adapter 是用户自己装的本机程序，Lobotomy 不防同机的恶意程序（AGENTS.md"加测试前"）。

扩展用带命名空间的键 `x-<作者>.<名字>`，不认识的忽略，与 worker 协议相同。

## 4. 操作（后端 → adapter）

所有 ID 由后端生成，同时作为幂等键。

| 操作 | 作用 | 回执 |
|---|---|---|
| `hello` | 协商协议版本，交换能力声明 | 能力清单 |
| `call(call_id, op, args)` | 执行一个操作 | `done`（带结果）、`failed`（带原因）或 `unknown` |
| `begin_login()` | 开始登录或重新登录 | 给用户看的网址或说明；登录的结果用 `status` 事件报告 |
| `subscribe(after_seq)` | 订阅事件 | 先给当前状态，再补发 `after_seq` 之后的事件 |

- **幂等**：同一个 `call_id` 重复调用，返回第一次的结果。adapter 不能确定一个写操作是否做成时（例如重启之后），回 `unknown`。后端不自动重试，由 Angela 先查证再决定（tech-plan.md §4.3）。
- **授权**：写操作的授权由后端检查（§6）。adapter 看不到授权，它收到的写操作都已经授权。
- **结果**：文字、可选的结构化数据，以及外部对象的引用 `(来源, 对象 ID, 版本)`。版本是 adapter 给的不透明字符串，例如网盘文件的修订号。依据：外部已有版本管理的材料，核心只存这三项（tech-plan.md §4.1）。
- **大内容**：文件这类内容不放进 JSON。adapter 用 `put_blob(hash, chunk)` 按内容哈希分块传进 Lobotomy 的文件库，结果里只带哈希；很小的内容直接内联。做法与 worker 协议 §6 相同。adapter → 后端的请求只有这一种。

## 5. 事件（adapter → 后端）

事件带按来源单调递增的 `seq`。

| 事件 | 内容 |
|---|---|
| `status` | `ok`；`needs_login`，带原因；`limited`，带重置时间，拿不到就标 unknown；`error`，带原因 |

- 收到 `needs_login` 时，后端发"登录失效"的系统通知（tech-plan.md §5），界面上给出"重新登录"，点了就调用 `begin_login`。依据：授权失效、反复重连是调研中排第二的痛点，例如 [claude-code#65036](https://github.com/anthropics/claude-code/issues/65036)；交还控制要显眼（AGENTS.md 原则 5）。
- **不做外部变化的通知**（用户定）。理由：现在没有需要它的使用场景，等有了真实需求再做。需要时用能力声明加事件的方式加入，不影响现有的操作。

## 6. 后端给 Angela 的工具（暂定，用户定）

工具是固定的几个，不随 adapter 增减：
- `ext_sources()`：列出各来源的状态、操作和参数 schema。
- `ext_call(source, op, args, authorization?)`：`read` 操作直接转给 adapter。`write` 操作必须带 `authorization`，值是用户某条消息的 ID；后端按 tech-plan.md §4.6 检查后才转给 adapter。
- 后端按 schema 校验参数，不合格时返回错误，由 Angela 修正。

理由：增减 adapter 不改变 Angela 的工具定义。工具定义变了，她会话的提示词缓存会从工具定义处失效（推断，没有实测）。代价：操作的参数不在原生的工具定义里，模型更容易填错，由后端的校验兜底。备选是每个操作展开成一个工具。

记入图（图在第 2 步实现，见 tech-plan.md §7）：
- 读到的内容记为 observation，来源是 external。文件进文件库，节点引用哈希。
- 做成的写操作记为 action。

## 7. 已知风险：提示词注入不处理（用户定）

- **风险**：读到的外部内容进入 Angela 的会话，其中的指令可能影响她。她有命令和网页读取工具（harness-adapter.md §1.6），借这些工具外泄内容，不经过 adapter，也不需要登录。
- **理由**（用户定）：按"不防恶意"的原则处理；而且 Angela 不经 adapter 通常连不上任何来源，大部分来源都要登录。
- **谁会发现**：每次读写都记入图（§6），用户可以按 Angela 的 turn 回看她做了什么（tech-plan.md §4.1"历史版本"）。
- **人工处理**：用户停止 Angela，再到外部系统中撤销这个 adapter 的授权。

## 8. 0.1 不做

- 远端传输，随 remote 一起做。
- 外部变化的通知（§5，用户定）。
- 取消正在执行的调用；进度事件。
- 预先给的长期授权，沿用 tech-plan.md §4.6。

## 9. 已定与待决

**已定（用户定）**
- §0 的五条前提。
- 不做外部变化的通知（§5）。
- 提示词注入不处理（§7）。
- Angela 用固定的 `ext_sources` 与 `ext_call`（§6），暂定。
- 实例退出后不自动重启（§2）。
- `effect` 必填（§3）。
- 结果为 `unknown` 的调用不自动重试（§4）。
- 数据目录的位置（§2）。

**实现时的选择**（用户没有逐条确认）
- 能力声明中有操作缺了 `effect` 时，拒绝整个声明（§3）。

**待决**
1. 第一个 adapter 接哪个外部系统。
2. adapter 程序怎样分发和安装：随 Lobotomy 一起发，还是由用户自己装。
3. worker 的任务需要外部材料时怎么办。
4. 远端实例的传输与认证，随 remote 一起定。
