> Status: 草案 v0.1（2026-10-11），§7 的待决问题待用户确认

## 0. 目标与边界

**目标**：把界面从"开发者临时凑的"变成能长期使用的工作台。先做主路径：与 Angela 的对话、"等你决定"、任务面板。

**边界**：

- 不改业务语义、命令与后端协议。P0–P5 只改前端；P5 的自绘标题栏另改 Electron 主进程。P6 的范围见 §7 Q3。
- 不改通知规则。通知属于 M4 的范围（roadmap.md M4）。
- 性能约束不变（frontend.md §0、§4.2）。
- 与 M4 的验收并行。P0、P1 只改外观，不改变验收要看的行为。

## 1. 现状审计

方法：`e2e/screenshots.spec.ts` 用真实后端加假 Codex 截项目视图、任务面板、设置与暗色；另用模拟的 WebSocket 临时截了「全部」（Angela 的对话、四类"等你决定"、共识）。窗口 1400–1440 × 860–900。

**视觉**

- 层级平。正文、区块标题、卡片标题都在 12–14px，粗细接近。同一级标题在各处字号不同：任务面板 17px，「全部」16px，右侧栏 13px。
- 没有间距刻度。padding 散落在 3、4、6、8、10、12、14、18、24px。圆角有 6、8、10、16px 四种，阴影有三种写法。
- 没有图标。⚙ ↑ ↓ ▶ ● 都是 Unicode 字符，粗细与对齐随字体变化。
- 强调色过载。主按钮、链接、选中项、"运行中"、"已转给"、按钮悬停的边框都是同一个蓝。
- 计数徽标用错误色。「全部」、每个项目、"等你决定"上都是红色数字，"等你看一下"看起来像报警。
- 角色没有身份。frontend.md §2 写了"每个角色一个标识色或头像"，还没有实现；所有 role 名都是同一个棕色。
- 用户的消息是 85% 宽的浅蓝块，Angela 的回复是带边框的卡片。宽窗口中一行超过 80 个汉字。
- 运行状态不明显：项目列表中是一个 10px 的绿点，对话中是一行"运行中 1:01"蓝字。
- "等你决定"、Workboard、共识、附件都是同一种 1px 边框加 8px 圆角的框，分不出主次和类型。
- 按钮是网页写法：悬停时边框变蓝，鼠标是手形。
- 设置页（Primer 式）是现在最整齐的一页。

**信息与交互**

- 主对话中露出内部词汇："turn 正常结束"、"调用 lobotomy.assign"、"（item_3）"、"基于集成版本 base0000 · 检查设置第 2 版"。其中一部分是有意的：附件写明版本是可争辩性的要求（manager-actions.md §2.1）；"turn 正常结束"是为了不与任务完成混淆（frontend.md §7.3）。要改的是层级，见 §2 原则 5。
- "等你决定"的四类条目（问题、额度、验收、受阻）长得一样，只有额度是黄色。卡片没有时间，也没有"新"的标记。
- Workboard 中角色行与任务行在视觉上没有归属关系。状态是彩色文字加灰色小标签。
- 任务面板中「验收」「退回…」「暂停」「放弃」并排，样式相同。「放弃」点一下就执行，没有确认。交付说明、你的原话、完成条件、验证、改动、记录用同一级标题。
- 顶栏一直显示"● 已连接"，但只有断线时才需要它。
- toast 在底部正中，压在输入框上。
- 空状态只有一行居中的灰字。
- 没有键盘入口切换项目或打开任务。
- 已修：回复引用行显示 Angela 回复的 Markdown 原文（8d31c36）。

## 2. 原则

1. **三种来源，三种样式。** roadmap.md 的原则"事实、权威、判断分开"在界面上要看得出来（调研 §2.5）：
   - 判断：Angela 与各 role 的话。正文样式，带角色头像。
   - 权威：你的原话。引用块，写明时间。
   - 事实：运行时写的附件、验证结果、版本、"已转给"。元数据样式，带图标，可以点开；不用角色颜色。
2. **只有要你动手的东西醒目。** 运行中只有一个会动的点；"等你"用琥珀色；红色只给失败。依据：调研 §1.4 第 1、4 条，§2.2。
3. **先结论，证据一步可达。** 卡片与任务面板先写这件事对目标意味着什么、要你决定什么；证据在原处展开，不跳到别的页面。依据：调研 §2.1 的 Endsley 与 ParallelPilot，§1.5 的审查顺序。
4. **位置稳定，变化加标记。** 用户离开期间，列表不重新排序；新出现的条目加标记。依据：调研 §2.3。
5. **内部词汇降级，不删除。** turn、ID、提交号、检查设置的版本仍然可以看到，但放在次要层级：元数据行、悬停或展开。可争辩性需要它们，日常阅读不需要。具体范围见 §7 Q1。
6. **零运行时成本优先。** token、系统字体、CSS 动效。新依赖只有 lucide-react 与 Base UI 的少数组件，每加一个都记录包体积。

## 3. 视觉方向

依据调研 §3。下面是起点，具体数值在 P0 中按截图调整。

- **基调**：暖灰、低饱和，结构靠底色分层，少用线条（Linear 2026、Conductor）。现在的 `#fbfaf8` 方向对，保留。
- **分层**：侧栏比主区暗一档。卡片去掉大部分边框，用底色区分。阴影只给浮层：任务面板、弹窗、菜单、toast。
- **强调色**：只用于主按钮与焦点环。选中项用中性色的底；链接用正文色加下划线。
- **颜色体系**：中性色与强调色各 12 级，用 OKLCH 定义，按 Radix 的分工映射成语义 token（背景、元素、悬停、按下、边框、文字）。亮色与暗色各一套；暗色不用纯黑，表层越高越亮。
- **刻度**：
  - 间距 2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32px。
  - 圆角 4（标签、按键提示）/ 6（按钮、输入框）/ 8（卡片）/ 12（弹窗）。
  - 阴影 2 级：面板与菜单一级，弹窗一级。列表行与卡片不用阴影。
  - 字号 12（元信息）/ 13（列表、侧栏）/ 14（正文）/ 16（区块标题）/ 20（页标题）。中文段落行高 1.6–1.7。
  - 字重只用 400 与 600。雅黑 UI 没有 600，中文会显示为粗体，接受这一点。
  - 时长 100ms（悬停、按下）/ 160ms（菜单、提示）/ 220ms（面板），一条 ease-out 曲线；减弱动效时归零。
- **字体**：系统字体，不捆绑字体文件。
  - 界面：`"Segoe UI Variable Text", "Segoe UI", "Noto Sans", "Microsoft YaHei UI", "Noto Sans CJK SC", "Source Han Sans SC", sans-serif`。雅黑 UI 排在 Noto CJK 前，避开 Windows 100% 缩放下的发虚。
  - 等宽：`"Cascadia Mono", Consolas, "DejaVu Sans Mono", "Microsoft YaHei UI", "Noto Sans Mono CJK SC", monospace`。
  - 消息正文开 `text-autospace`，代码、路径、diff 中关闭。
- **图标**：lucide-react，16px，描边 1.5，只用具名导入。只用在导航、工具栏按钮与状态标记上，正文不放装饰图标。
- **状态**：5 种外观，每种都由形状、颜色、文字共同表示（调研 §3.5）。文字沿用 `format.ts` 现有的说法，外观只是归类：

  | 外观 | 形状与颜色 | 现有状态 |
  |---|---|---|
  | 运行 | 实心点，缓慢脉冲，蓝 | 正在跑 turn、即将开始、验证中 |
  | 等你 | 空心环，琥珀 | 停下等你决定、待验收、Angela 的问题 |
  | 失败 | 三角，红 | turn 异常结束、验证失败、项目打不开 |
  | 完成 | 对勾，绿 | 已完成、验证通过 |
  | 静止 | 灰点 | 空闲、排队、暂停、已放弃、回复在排队 |

- **角色身份**：每个 role 一个固定颜色，从 6 个色相中选。头像是名字的首字母加色底。按名字固定分配，未知的名字按名字取色。用户不加头像。

## 4. 分阶段

按顺序做。P0 与 P1 改变整体观感最多，风险最低，先做。

### P0 地基（不改行为）

- 按 §3 写 token，把 `styles.css` 中的颜色、圆角、字号、阴影字面量换成 token。Shiki 的代码配色除外。
- 字体栈与 `text-autospace`。
- lucide-react 替换 ⚙ ↑ ↓ ▶ ● ✕ ← 等字符。
- 窗口的基础手感：
  - 按钮与列表行用 `cursor: default`，手形只给外部链接。
  - 统一的 `:focus-visible` 焦点环。
  - 标题栏、侧栏等界面框架不可选中文字；消息与代码仍可选中。
  - 窗口失焦时淡化选中态。
  - Electron 窗口 `show: false` 加 `ready-to-show`，背景色与页面一致，避免白闪。
- 截图场景：把 `e2e/screenshots.spec.ts` 扩成固定的场景集，加上模拟的「全部」（Angela 的对话、四类"等你决定"、共识）、任务面板、设置，亮色与暗色各一张。仍然只在设了 `SCREENSHOT_DIR` 时运行。

完成标准：

- `styles.css` 的 `:root` 之外没有颜色字面量。
- 文字 token 的对比度达到 WCAG AA：正文 4.5:1，大字与图标 3:1。由一个小脚本检查。
- e2e 不需要修改。

### P1 身份与状态

- `RoleAvatar` 与 `StatusPill` 两个组件。项目列表、Workboard、任务面板、对话中的 turn 状态都用它们。
- 计数徽标改用琥珀色，不再用错误色。
- 运行中的点只在可见时脉冲；减弱动效时不动。
- Workboard 中，任务行缩进在执行者的角色行下，显示归属关系。
- 角色行显示本次 turn 的运行时长，turn 结束后停止计时。

完成标准：同一状态在所有位置的形状、颜色、文字相同；去掉颜色后仍能分辨状态。

### P2 对话

- **版式**：
  - 阅读区宽约 720px，居中。
  - Angela 与 role 的话不加框，左侧是头像与名字。
  - 你的消息靠右，浅底块，最大宽度约 560px。
  - 运行时的消息是一行细的系统提示，点开看全文（保持 frontend.md §7.3 的收起规则）。
- **三种来源**（§2 原则 1）：
  - 原话引用块：写明"你的原话"与时间。
  - 附件：一行，依次是图标、项目、对象、状态、时间。版本信息放在第二行，次要样式。已过期或已被取代的，标记保持醒目。
  - "已转给"：事实行样式，带图标，不再用链接蓝。
- **工具调用**：连续的工具调用合成一行，例如"用了 3 个工具 · 最近：Read login.tsx"，点开看每一个。正在运行的那一个单独显示当前动作与已运行时间（调研 §1.4 第 5 条）。
- **turn 分隔**：异常结束的 turn 保留醒目的说明。正常结束的 turn 怎么显示，见 §7 Q1。
- **输入框**：
  - 高度随内容增长，有上限。
  - 显示现在的按键：Enter 发送，Shift+Enter 换行。
  - 回复的对象显示为输入框上方的一个标签，可以取消。
  - 发送按钮改为图标按钮，禁用时不再是一大块浅色。

完成标准：

- 搜索高亮、折叠展开、"回到最新"的 e2e 通过。
- CI bench 摘要中，长对话的输入延迟与滚动不变差。

### P3 等你决定

- **按类型区分**。每类一个图标与颜色：
  - 要你回答：Angela 的问题、执行者的问题。
  - 出了问题：turn 没能启动或异常结束、任务受阻、额度不足、没人推动的任务、后台作业失败。
  - 等你验收。
  - 任务外的改动。
- **卡片结构**：
  - 第一行：类型图标、项目、多久以前。
  - 第二行：一句话写要你决定什么。
  - 右侧：主操作。
  - 原始错误、路径列表等收起。
- 分组与排序见 §7 Q2。

完成标准：e2e 中关于"等你决定"的测试按新文案更新后通过。

### P4 任务面板

- **头部**：
  - 标题、状态、第几轮。
  - 主操作是「验收」，次操作是「退回…」。
  - 「暂停」与「放弃」收进"更多"菜单。「放弃」用危险样式，并确认一次，与设置中的归档相同（frontend.md §7.8）。这是本专项唯一新增的一步确认，理由是「放弃」不能撤回，现在又紧挨着「验收」。
- **结论条**：放在头部下方，写本轮验证的结果、基于哪个集成版本、改了几个文件（+/− 行数），以及试用入口。
- **正文**：顺序保持 frontend.md §7.4，只调层级。同级标题统一；记录改为带图标的时间线。
- 面板滑入用 220ms 动画。面板是区域不是对话框（frontend.md §7.4），主区不变暗。

完成标准：`e2e/m1.spec.ts` 的整条流程通过。

### P5 窗口与导航

- **自绘标题栏**（`titleBarStyle: 'hidden'` 加 `titleBarOverlay`，Windows 与 Linux 都支持）：
  - 左边是应用标记与当前位置（「全部」或"项目 · 分支"）。
  - 右边是搜索、设置与系统的窗口按钮。
- **连接状态**：只在断开或重连时显示，形式是一条横幅。
- **项目列表**：
  - 每行有状态点与条数。
  - 「全部」一行带 Angela 的头像。
  - 「+ 新项目」改成列表末尾的一行。
- **命令面板（Ctrl+K）**：切换项目、打开任务、打开设置、新建任务。用 Base UI 的 Dialog 与 Autocomplete，不另引入 cmdk，避免同时引入两套底座。
- **toast**：移到右下角，最多同时 2 条，悬停时暂停计时。
- **空状态**：一句话说明这里会出现什么，加一个主操作。
- **设置页**：结构不变，套用新 token。

完成标准：`e2e/electron.spec.ts` 通过。

### P6 回来时的接续（待 §7 Q3）

- 前端在本机记下：每条对话看到了哪里，见过哪些"等你决定"条目。存在 localStorage 中，读写失败时不显示标记。
- 对话中加"上次看到这里"分隔线。
- 新出现的卡片加"新"标记，看过后消失。
- 用户离开期间，列表不重新排序。
- "离开期间发生了什么"的汇总不在本专项中，它属于 #50 的问题。

## 5. 做法

1. 每个阶段拆成几个提交，按 AGENTS.md 直接推 main。只改样式的提交，本地运行 `npm run typecheck`、`npm test` 与受影响的 e2e。
2. 改动前后用截图场景各截一组，生成本地 HTML 对照页给用户看，不发布到网上。P0 与 P1 完成后先给用户看一次，方向认可后再做 P2。之后每个阶段完成时都附对照页。
3. 无障碍名称尽量不变，因为 e2e 用它们定位。文案变了的，在同一个提交中改测试。
4. 新依赖记录 `vite build` 前后的产物大小。
5. 改了对话渲染的提交，看 CI 的 bench 摘要（AGENTS.md）。

## 6. 不做或暂缓

- **不做**：
  - Mica 与亚克力：只有 Windows 11 有，社区报告过缩放问题。
  - 动画库（Motion 等）、Storybook 或 Ladle、捆绑 CJK 字体。
  - 数字置信度、自主度滑杆（调研 §4 第 2、3 条）。
  - 看板形态。
- **以后再议**，它们改变行为，不在本专项中：
  - diff 上的行内评论，一次退回给执行者（调研 §1.4 第 7 条）。
  - 改动只看"这一轮相对上一轮"（调研 §1.4 第 8 条）。
  - 卡片上的下一步按钮代替用户发一条指令（调研 §1.4 第 9 条）。
  - 验收时记录看过哪些证据（调研 §4 第 7 条）。

## 7. 待决问题

**Q1 内部词汇降到什么程度？**

- 建议：
  - 正常结束的 turn，分隔线只留时间，不写"turn 正常结束"。
  - 消息与附件中的 item ID、提交号、检查设置的版本，放进元数据行或悬停提示。
  - 工具调用显示工具名，不显示 `lobotomy.` 前缀。
  - 异常结束、过期、被取代仍然醒目。
- 涉及 frontend.md §7.3 的写法，是**语义更新**，需要用户确认。

**Q2 "等你决定"按类型分组，还是按项目分组？**

- 建议：「全部」中按类型分组（要你回答、出了问题、等你验收、任务外的改动），每张卡片标出项目。进入项目后，同样按类型分组。
- 依据：同类产品都把"等你回答"与"等你验收"分开，并把需要你的排在最上（调研 §1.4 第 2、3 条）。
- 反方：按目标组织信息（调研 §2.1 Endsley），而项目接近目标。
- 现在 frontend.md §2 写的是「全部」按项目分组，M4 的条目"分组与条目不变"。改为按类型是**语义更新**。

**Q3 "回来"的提示要不要放进本专项？**

- 建议：做 P6，只在前端做"上次看到这里"与"新"标记，不改后端，也不加 Angela 的判断。
- 依据：这是 #50 的第一优先级"降低用户回来恢复工作现场的成本"中，运行时可以确定的那部分。
- 理由：标记只依据事实，即用户看过什么、什么是新的，不涉及 #50 的三组开放问题。
